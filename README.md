# chiryoinDB — 整骨院 患者管理シート（プロトタイプ）

整骨院の運営会社向け患者管理シート。会社 → 院 → 患者 の階層、月次シート、権限管理を備えた Web アプリ。

## 起動

```
npm start        # http://localhost:3000  （Node 22.13+、依存パッケージなし）
npm test
```

初回起動時にサンプルデータ（A社/B社、各権限のアカウント）を作成します。
ログインは開発用（アカウント選択）。本番では Google ログインに置き換えます（`DEV_LOGIN=0` で無効化）。

## 用途
交通事故の売上コンサル用。交通事故以外の患者情報は入れません。シートの1行は「事故案件」です。

## 実装済み
- 権限: 運営（自社＝システム提供側）/ 会社管理者 / 院担当者（サーバー側で全APIを検証。他社・他院のデータは参照・更新不可）
- 階層: 会社 → 院 → 事故案件。患者は氏名+生年月日で会社内一意。同一人物が複数の事故に遭った場合は、同じ患者の別案件（`C1-0001-1`, `C1-0001-2`）になる
- 項目: 氏名・生年月日・事故日・初診日（案件の基本情報。初診日は事故日以降）と、月次の7項目
  通院日数（10日/15日/20日時点・末日）、請求金額、請求部位数、弁護士紹介済み（チェック）
  - 通院日数は上限（10/15/20日・その月の日数）と「後の時点が前より少ない入力は不可」を検証
  - 累計通院日数は「末日」の月次合計から自動計算（入力不可）
- 月次シート: 新規案件 / 既存案件を分けて表示。翌月を開くと既存案件が「未確認」で並び（弁護士紹介済みだけ前月から引き継ぎ、他は0から入力）、院担当者が「継続」「終了」を確認。終了した案件は以降の月に出ない
- 編集ロック: 月が終わって2か月が過ぎた月は編集不可。解除・再ロックは運営のみ
- マスター項目の会社別オン/オフ・名称変更は運営のみ（会社管理者は不可）
- 入力制限: 書き込めるのは有効な項目の値と事故日・初診日だけ。累計・合計はサーバー計算で、書き込みAPI自体が受け付けない
- 会社管理者は所属会社の院・アカウントを追加可能

## 本番化の予定
- 認証: Firebase Authentication（Google）。DB: Firestore。ホスティング: Firebase Hosting + Cloud Functions もしくは Cloudflare
- `db.js` と `/api/login` の差し替えで対応（API・画面は流用）
